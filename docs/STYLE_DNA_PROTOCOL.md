# Style DNA 协议

这套协议的存在，是为了防止视觉模型答错问题。

## 第一步 —— 识别媒介

海报、演示文稿、数据看板、网页 UI、移动端 UI、插画、摄影或数据可视化。

不同媒介的侧重点不同。看板需要密度、网格与图表处理；海报需要构图、字体、质感与主体摆放。

## 第二步 —— 分离内容与风格

分析器显式列出内容，只是为了证明它已经把内容与可复用的风格分开。

**内容示例**

- 一栋建筑；
- 一个人；
- 字面的标题文案；
- 品牌 logo；
- 某个具体的 KPI 数值。

**风格示例**

- 非对称网格；
- 低饱和暖中性色板；
- 高留白；
- 超大衬线标题字；
- 细微纸纹；
- 一个克制的点缀色。

## 第三步 —— 把判断转成规则

差输出：

```text
极简
现代
高级
```

有用的输出：

```text
高外部留白
低装饰密度
一个焦点点缀色
强烈的标题/正文字号对比
左侧主导对齐
柔和的图像对比
```

## 第四步 —— 解释为什么成立

光有情绪标签不够。“平静”应该绑定到可观察的视觉证据，比如低饱和、高留白与柔和对比。

## 第五步 —— 生成反向 Style DNA

避免清单是一等公民输出，因为生成失败往往来自加错了视觉套路：厚重光晕、高光 3D、彩虹渐变、超大圆角卡片或过度锐化。

## 第六步 —— 迁移，不要克隆

一条风格规则可以随媒介改变实现方式：

- 海报里的纸纹 → 网页上微妙的背景纹理；
- 编辑衬线层级 → 演示文稿的标题 / 正文层级；
- 圆角 UI 语言 → 图表标签与图例的处理；
- 点缀黄 → 高亮的数据信号。

协议迁移的是逻辑，不是字面的像素。
